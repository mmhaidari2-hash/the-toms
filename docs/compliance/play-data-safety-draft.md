## Definitions used

- [Play Data safety form](https://support.google.com/googleplay/android-developer/answer/10787469): “Collect” means data transmitted off the device, including by a library or SDK, to the developer or to a third party. On-device processing that is not sent off the device is not collected. “Sharing” is transfer of collected data to a third party, including an on-device transfer to another app. A service provider acting on the developer’s instructions, and a transfer the user starts and reasonably expects, are not declared as sharing. Approximate location is an area of at least 3 square kilometers; precise location is a smaller area. Each category has its own note that location inferred from an IP address or an access point name is disclosed under that category. An IP address by itself does not choose the category. Ephemeral processing is still answered in the form, and is disclosed on the store page only if it fails Play’s memory-only test.
- [User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311)
- [What users are told the section means](https://support.google.com/googleplay/answer/11416267)
- [RevenueCat: Google Play’s Data safety](https://www.revenuecat.com/docs/platform-resources/google-platform-resources/google-plays-data-safety) — this page is for an app that **uses** RevenueCat.
- [GitHub Pages: data collection](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) and [GitHub General Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement) (effective date on the page: 27 April 2026).

## What still blocks a final form

- Publisher legal name, contact, and a real privacy-policy URL (Q03 and the public page).
- A decision on the download host: retention, whether the publisher is the controller or GitHub is only a service provider, international-transfer paperwork, and whether any location category applies. An IP address alone does not make that category precise.
- A packet capture was not done. Before `Purchases.configure`, plugin registration and `CurrentActivityTrackerInitializer` show no network call in the packaged bytecode. Code after `configure` was not traced.
- Whether any later build will turn purchases on. If it does, this map is not the answer.
- Children’s assessment / DPIA and the store age declaration. The app does not check age, and legacy child profiles remain.
- No Play Console account was opened and nothing was submitted.
